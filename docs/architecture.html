動漫立方 AniQube
架構與資料流程

類 Netflix 的動畫瀏覽網站：影片全部來自 YouTube 官方頻道，只用 YouTube 播放器嵌入播放。純靜態網站，沒有後端、沒有帳號、沒有資料庫；片庫每天由 GitHub Actions 同步成 JSON，部署在 GitHub Pages。

3片源頻道
630作品（卡片）
976播放清單／單篇
≈3,000每日 YouTube 配額單位
42自動測試

01概觀與限制

網站分成兩半：同步端（sync/，Node.js，每天在 GitHub Actions 跑一次）把 YouTube 頻道整理成片庫 JSON；前端（src/，Vue 3 + Vite + TypeScript）是純靜態單頁應用，只讀這些 JSON，搜尋、篩選、排序都在瀏覽器裡做。

沒有後端

YouTube 搜尋配額一天只有 100 次，不可能即時查；片庫每天建一次存成靜態檔（ADR 0001）。

只能嵌入 YouTube

不能修改或遮擋 YouTube 播放器（API 服務條款）。倒數、提示一律放在播放器下方。

沒有帳號

繼續觀看、片單、看過紀錄、設定都存在瀏覽器 localStorage；換裝置靠備份檔。

配額 10,000／日

只有「抓 YouTube」這一步花配額。抓到的原始資料存成快取，改任何規則都能 0 配額重跑。

名詞（作品、季、配音版、合輯、單篇、看過、有新集⋯）的定義以 CONTEXT.md 為準。

04同步管線（npm run sync）

一次同步依序做下列事。只有第 1 步花 YouTube 配額；設 USE_RAW_CACHE=1（npm run rebuild）會跳過第 1 步、改讀 sync/cache/raw.json，改任何規則都用這個，0 配額、約 25 秒。

  1. 抓 YouTube（fetchChannel）≈3,000 單位每個頻道抓：會員清單（UUMO 開頭的非公開清單，用來扣掉會員限定影片）、上傳清單、所有播放清單與其影片 ID、全部影片細節（標題、長度、上架時間、可否嵌入、年齡與地區限制、觀看數、說明）。這一步不套任何過濾規則，用量只隨頻道內容變；結果原樣寫進 raw.json。
  2. 過濾與分季（buildChannel → buildSeasons、buildStandalones）classifyVideo 判斷每支影片可不可播：直播、會員限定、台灣封鎖、長度不符、標題命中搶先看或排除詞的都剔除；不能嵌入或年齡限制的保留，標成站外集。一個播放清單成為一季，集數依標題（EP12、第12話、「第07-11話」取第一個數字）排序，合併版若每集都另有單獨上傳就拿掉。不屬於任何季、標題像劇場版／OVA／特別篇的長片成為單篇。
  3. 對應 AniList（match）人工對應表優先；否則用 cleanTitle／candidates 清出候選名，在離線資料集（buildIndex）找同名條目，多筆時依標題的季數、年份、劇場版字樣挑一筆；中英黏在一起的名稱（splitName）也拆開試。結果標記 how：manual／single／season／year／first／split，後四種會列進報告的 guessed 供抽查。
  4. 取作品資料（anilist）對上的編號每 50 筆向 AniList 查一次：題材、標籤、評分、人氣、狀態、首播、簡介、封面、橫幅，以及續集／前傳關聯（給第 5 步合併用）。成人類題材直接丟棄。
  5. 合併成作品（groupWorks）見第 5 節。
  6. 組輸出每部作品：卡片資料取最新一季、年份取首季、人氣熱度取各季最大、篩選用所有季題材標籤的聯集（facets）；簡介優先用頻道播放清單的中文說明（cleanDesc 清掉宣傳、騰訊轉繁體），沒有就退回 AniList 英文（descLang）。
  7. 保護與寫檔作品數比上次少超過三成就中止、不覆蓋（防止 API 異常把片庫清空）；否則重寫 public/data/。

每一步的「改了什麼規則要重跑到哪一步」另見 dataflow.html。

05作品分組規則（groupWorks，ADR 0003）

一張卡片＝一部作品，只在同一片源頻道內合併。

  1. 標題去掉季數、範圍（S1-S3）、配音標記後名稱相同的季歸同一部；季名相同、配音不同的是同一季的配音版；同季同配音的重複上傳留集數多的。單篇標題含某作品名（取最長、至少 3 字）就歸入該作品。
  2. 三個合併訊號（union-find）：共用 YouTube 影片超過較小那部的一半；對到同一個 AniList 編號；在 AniList 上互為續集／前傳。寫在 manual-works.json 的作品不參與自動合併。
  3. 合輯與配音版配對標題看得出、或集數完整包含另一季的是合輯；合輯九成以上的集在別的清單都有就不列。名稱不同但對到同一個 AniList 編號、語言互補的季，配成同一季的配音版（例如 Dr.STONE 的粵語與日語清單）。
  4. 命名與排序作品名取原聲首季中最短的名稱；季有季數照季數，沒寫季數的（「續」「完」「The Final Season」）依 AniList 首播時間插入（orderSeasons）；單篇排最後。

06資料格式

public/data/index.json（首頁與瀏覽頁一次載入，約 550 KB）

{ generatedAt, channels: [{ key, name }], works: Work[] }
Work = { id, title, channel, origin, alt[],          // alt：各季名稱與別名，給搜尋用
         genres[], tags[], facets[],                // 卡片顯示最新季；facets＝所有季的聯集，給篩選用
         year, season, status, format, score, popularity, trending,
         seasons, eps, totalEps, views, updated,    // updated：最新一集的上架時間
         thumb, cover, banner, anilistId, how }

public/data/works/<id>.json（進作品頁或播放頁時才載入）

{ id, desc, descLang: 'zh' | 'en',
  members,                                         // 有會員限定集時，該清單 ID（作品頁連到 YouTube）
  seasons: [{ name, kind: 'season' | 'collection' | 'special',
              dubs: [{ lang, list, episodes: [{ id, n, title, sec, ext }] }] }] }

作品 ID 是「頻道＋作品名」的雜湊，名稱不變就穩定；播放頁網址 /watch/<作品>/<影片 ID>，影片 ID 在作品內唯一，所以季與配音版都能從它反推（work.ts 的 locate）。

public/data/report.json（給人看的同步報告）

units 配額用量、unmatched 沒對上 AniList 的清單、guessed 用猜的對應（建議抽查）、dropped 成人類、desc 各頻道中文／英文簡介數、epDescSamples Ani-One 第 1 集影片說明抽樣、counts。

sync/cache/raw.json（不進 git）

每個頻道 { members[], uploadIds[], lists[{ id, title, desc, n, videoIds[] }], videos[{ id, title, desc, at, live, sec, views, embeddable, age, twBlocked }] }。影片的 desc 欄位在 2026-11-18 之後的完整同步才有。

/aboutAbout版權、資料來源、隱私

模組

檔案職責
data.ts載入 index.json（全站快取一份）與 works/<id>.json。
catalog.ts篩選、排序、主打挑選、卡片資訊列、集標題清理（去掉宣傳尾巴與重複作品名）。
work.ts作品內的位置（季、配音版、集）：locate、nextSpot（季末接下一季）、switchDub（換配音對到同一集數）、episodeRows（無此配音）。

preview.ts ＋ Preview.vue卡片預覽：桌面滑鼠停 450ms 放大成預覽卡，觸控點擊開底部面板；全站一份，畫在橫列外面以免被裁切。

share.ts系統分享選單或複製連結、提示訊息、時間格式。
style.css「朱印映畫館」設計：色彩、字級、間距 token，思源宋體標題、朱紅強調色。

08本機資料與備份

localStorage key內容
aniqube:progress:works繼續觀看：作品 → { 影片 ID, 秒數, 時間, 這集長度 }
aniqube:list:works我的片單：作品 ID 陣列，新加的在前
aniqube:watched:works看過的集：作品 → 影片 ID 陣列（播放超過 30 秒）
aniqube:last:works每部作品最後觀看時間（觀看紀錄排序用）
aniqube:seen:works有新集的基準：上次看這部作品時它的最後更新時間
aniqube:settings設定（目前只有 autoplay）

個人選單的「匯出備份檔」把以上全部存成 aniqube-備份-日期.json（{ app: 'aniqube', version: 1, list, progress, watched, seen, last, settings }）；匯入時先驗證格式，再合併：片單與看過取聯集、進度留較新的、設定以備份檔為準。

09設定與人工檔案

sources.json

欄位作用
channels[]key、頻道 ID、名稱、製作國（決定原聲語言）、最短集長 minSec；可覆寫 memberMarkers（騰訊設成空字串：它的「会员抢先看」在 YouTube 上是公開影片）。
maxSec / standaloneMinSec集長上限；單篇的最短長度。
titleDeny標題排除詞（預告、花絮、直播、連播、音樂會⋯），套用在清單與影片標題。
memberMarkers標題含這些字就視為搶先看、不收。
standaloneAllow / standaloneDeny單篇必須像劇場版／OVA／特別篇，且不能是談話節目、開箱、特攝。
excludeSeasons直接排除的清單 ID（混合多部作品的清單）。

人工檔案

manual-matches.json：{ "清單ID": AniList編號 }，null 表示刻意不對應；優先於自動對應。manual-works.json：{ "清單ID": "作品名" }，把清單指定到某部作品，被指定的作品不參與自動合併，所以也是「拆開合錯的作品」的方法。改完跑 npm run rebuild。

sync/taxonomy.mjs

AniList 題材（18 個，如動作、戀愛）與標籤（15 個，如異世界、轉生、刀劍）的中文名；只收這裡列出的，要增減改這個檔。

10部署與排程

  1. 觸發每天 UTC 20:00（台灣 04:00）排程、手動（Actions 頁 Run workflow）、或推送到 main。
  2. 測試npm ci → npm test（同步端＋前端）。
  3. 同步（只有排程與手動）npm run sync，金鑰來自 repo Secret YOUTUBE_API_KEY。CI 上沒有快取，每次都完整抓取，約 3,000 單位、7 分鐘。
  4. 提交資料機器人提交 public/data（每天一次，也讓排程不會因 60 天無活動被停用）。
  5. 建置與部署vite build → 上傳 dist/ → GitHub Pages：xupmtp.github.io/AniQube。
本機改程式後推送前先 git pull --rebase：機器人每天會推資料提交。public/data 衝突時保留任一邊都行，之後 npm run rebuild 重產即可。

11開發指令與測試

npm install
YOUTUBE_API_KEY=金鑰 npm run sync   # 完整同步（花配額），也會更新 sync/cache/raw.json
npm run rebuild                    # 用快取重跑所有規則，0 配額、免金鑰
npm run dev                        # 開發伺服器 http://localhost:5173/
npm test                           # 同步端與前端測試
npx vue-tsc --noEmit               # 型別檢查
npm run build                      # 產生 dist/

Node 需 22.15 以上（zlib.zstdDecompressSync 解壓離線資料集、--experimental-strip-types 跑 TS 測試）。測試慣例：非瑣碎的邏輯各留一個可執行的檢查，同步端有端對端測試（假的 YouTube／AniList），前端的純邏輯模組各有 *.test.ts。

金鑰只從環境變數讀，不得寫進任何檔案或提交。
